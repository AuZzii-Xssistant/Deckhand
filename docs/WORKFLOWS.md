# Rules, previews and diagnostics

1. Open **Rules** and add a rule. Use **Guided** to choose the folders, conditions and actions in order. Switch to **Full editor** to see the whole rule at once.
2. Choose a watch folder. Use a portable path such as `~Downloads` or `~Documents` when the rule should follow the current Windows user's folders.
3. Use **Check rule** to verify paths or try one file. Use **Simulate** to see what might happen when rules run in a particular order.
4. Preview the rule and inspect proposed changes, excluded files and problems. Start with a disposable folder when trying a new action.
5. Run it manually, enable watching, or set a schedule. Check the run mode in the rule editor. Rules that share a folder can be ordered in the Rules list. Narrow their conditions or add exclusions if they should handle different files.
6. Open **History** for file-level outcomes and supported undo actions. Open **Diagnostics** for CPU and memory readings and scan, preview and run activity. Previews make no changes, and closing a preset preview prompts before discarding its results.

**Presets** are reusable actions you can run against folders you choose. When moving to a new PC, use Settings to export your library and settings. Imported rules start disabled so you can review their paths and actions first.

For AI-assisted rules, see [the authoring guide](AI-AUTHORING.md) and [local MCP setup](MCP.md).
