    Actions and conflicts

    What happens to matching files, and what Deckhand does when a name is taken or a value is missing.

    Actions run top to bottom on each matching file. Each action has its own options, in the gear next to it.

    The first screenshot is the Then step of the rule Invoices to Documents. It has one action, Move file, with a destination made of text and the Date modified yyyy variable. The gear at the end of the row holds If the file already exists and the other options of that action.

    The actions

    ActionWhat it does
    Move fileMoves the file to a folder, keeping its name.
    Copy fileCopies it. Later actions can continue on the copy.
    Rename fileGives it a new name. The extension is kept.
    Change extensionChanges the extension only.
    Sort in foldersPuts the file in a subfolder by type, extension or date.
    Zip / ExtractAdds the file to a zip, or unpacks an archive.
    Send to Recycle BinRecycles the file. Windows can restore it.
    Delete fileDeletes permanently. This cannot be undone.
    Run command / Run saved scriptRuns a program or script for each file.
    Log / NotifyWrites a line to the log, or shows a message.
    Remove folder if emptyRemoves the file's folder when it has become empty.

    Details and options for each are in the Actions reference.

    The second screenshot is the end of the rule Release builds: sign, then publish to the NAS. It has two actions. Run saved script runs the script Sign release with the file path as its argument, then Copy file copies the signed installer to \nas eleasesdeckhand.

    When a file already exists

    Each move, copy, rename and similar action has an If the file already exists choice:

    ChoiceResult
    Rename the new file (default)The new file becomes name_2, name_3 and so on.
    SkipThe file is left where it is.
    Overwrite the old fileThe old file goes to the Recycle Bin, then the new one takes its place.

    The starting choice for new actions is in Settings → Behavior. Existing rules are not changed when you change it. Overwrite never recycles a folder.

    If a value is missing

    When a {variable} in a name or folder has no value for a file, the action can:

    • Skip the file: it is left alone and later actions continue.
    • Use a fallback you typed.
    • Mark the file as a problem: the file's remaining steps stop and it shows as skipped with the reason "no value".

    You can also put a fallback inside the text, for example {client|Unknown}.

    Safety rules for steps

    • If a step fails or is skipped, later steps that would delete or recycle the file do not run. A copy followed by a recycle can never lose the only copy.
    • A failed step stops that file's remaining steps.
    • Copy, zip, extract and run commands wait while the file is still being written.
    • Extract never overwrites existing files.
    • Run commands that take longer than 10 minutes are stopped.

    Mirror subfolders

    With Include subfolders on, a Move, Copy or Zip action can keep the folder structure. C:\In\a\b\x.txt goes to D:\Out\a\b\x.txt instead of D:\Out\x.txt. The option is in the action's gear and shows an example. Undo removes folders the step created once they are empty.

    Sort in folders

    Sort creates subfolders under a base folder and puts each file in the right one:

    Sort byFolder name
    TypeCategory\Subtype, for example Microsoft Office\Word
    ExtensionPDF
    Year2026
    Month2026-11
    Day2026-11-19

    Extensions that are not in the file-type list go to Other\EXT. Dates use the file's modified date.

    Recycle or delete

    Send to Recycle Bin can be undone from Windows. Delete file cannot. When in doubt, recycle. Run a rule with Log first if you are unsure what it will catch.
