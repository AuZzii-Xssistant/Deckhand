    MCP safety and privacy

    What a connected AI client can see and do, how review works and what your AI provider may see.

    The design rule is simple: the AI proposes and Deckhand's window decides. Every change that matters goes through a review you open yourself.

    Why imported rules arrive switched off

    A rule written by a program can look right and still match more files than you meant. A rule that is on starts working as soon as a file appears in its folder. So a rule from an assistant is always added with enabled off: deckhand_prepare_draft and deckhand_submit_rule force it, and an edit applied from a request leaves the rule off too. You read it, preview it on a real folder and switch it on yourself.

    The draft workflow

    1. Author: the assistant reads the catalogue and writes a draft.
    2. Validate: deckhand_validate_draft reports errors and warnings. The assistant fixes them.
    3. Import switched off: deckhand_submit_rule (or import of the JSON from deckhand_prepare_draft).
    4. Preview: you open the rule's preview in Deckhand. See Preview, run and undo.
    5. Enable: you switch the rule on, or run from the preview.

    What a connected client can do

    It canIt cannot
    Read the authoring guide, examples, schema and variable catalogueRead, list, move, copy or delete any file on your PC
    Validate drafts and prepare JSONSwitch a rule on, or save a rule as enabled
    With --data: queue one new rule, which arrives switched offSubmit rules that run a command or a script, presets, custom variables or scripts
    With --rule-edits: list and read rules that are off and have no command or script actionSee rules that are switched on, or rules with a command or script action
    Queue an edit or a preview request for your reviewApprove its own request, apply an edit, or start a scan or run
    Ask for the status of its own requestsSee file names or paths from a preview or run, only totals
    Change Deckhand's settings, schedules, presets or variables

    What a client reads with library access is exactly this, per rule: id, name, group and watch folder paths in the list and, when it reads one rule, the whole definition including conditions, actions, destination paths and notes. Names can repeat, so every call uses the id, and same_name_count tells the assistant when it must ask you which rule you mean.

    Review and the run gate

    • A proposed edit or preview request waits under Rules → Review AI requests.... You see the current and the proposed rule side by side in plain language, with the raw fields under Technical details.
    • Choices: Apply edit, Apply and preview (saves, keeps the rule off and opens the preview), Discard or Review later. For a preview request: Open preview.
    • A proposal is refused if the rule changed, was switched on or no longer exists since the assistant read it.
    • A preview opened this way is a normal Deckhand preview. A real run from it always asks for your confirmation, even if you turned run confirmations off. The preview expires after ten minutes, can be used once, is rebuilt and compared before the run, and is refused if the files or proposed operations differ. Live and scheduled work wait while the check and run happen.
    • Runs from such a preview are recorded in History and can be undone like any other run, with the source shown as MCP.

    Limits that protect you

    • A message from the client may be at most 1 MiB.
    • At most 32 submitted drafts and 32 review requests can wait at once.
    • Drafts that fail validation are never queued. A queued file that turns out invalid when the app reads it is set aside.
    • Scripts and commands never arrive through MCP.

    Privacy

    Deckhand's connection itself makes no network connection. It runs on your PC, started by your client. But the model that powers your client usually does not run on your PC, and everything the client reads can become part of what it sends to its provider.

    What your AI provider may see:

    • Anything you type in the chat.
    • Tool results: the catalogue and guide (not private), validation messages, and the content of drafts it writes.
    • With library access, for eligible disabled rules: names, group, folder paths, conditions, actions, destination paths, notes and text you wrote in them.
    • Aggregate totals (files scanned, matched, done, failed) of previews and runs you handed off.

    It does not see file names or file contents, because the connection cannot read your files. Choose a client and an account whose data policy you accept. Clear Use the library currently open in Deckhand if you do not want rule details to leave your PC. The assistant can still help you write and validate rules. For Deckhand's own data practices see the privacy policy.

    Warning

    Do not paste secrets such as passwords into a chat or a rule note. Anything in a rule definition that the client reads can reach its provider.
