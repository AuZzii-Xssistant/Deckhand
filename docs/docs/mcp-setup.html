    Set up an AI client

    Add Deckhand to Claude Desktop, Claude Code, Cursor, Codex or another MCP client.

    Deckhand does not change your client's settings. You copy one entry into the client's MCP configuration yourself. This page covers what to copy and how to check it.

    Get the entry from Deckhand

    1. Open Settings and find the AI integrations card. It has Connect an AI client... and View AI reference....
    2. Click Connect an AI client.... The same window opens from Help.
    3. Choose Claude Desktop / JSON or Codex / TOML. Use the JSON entry for Claude Desktop, Cursor and most other clients.
    4. Decide on Use the library currently open in Deckhand. It is ticked by default.
    5. Click Copy setup, then paste the entry into your client's configuration. Keep any other servers that are already there.

    Deckhand fills in the full path of the program and, with library access, the path of the profile folder that is open right now. Use its text rather than typing your own.

    Note

    A screenshot of the Connect an AI client window would help here. None is included yet.

    What the entry looks like

    With library access (the default):

    {
  "mcpServers": {
    "deckhand": {
      "command": "C:\\Users\\ScriptKiddyMonkey\\AppData\\Local\\Deckhand\\Deckhand.exe",
      "args": [
        "--mcp",
        "--data",
        "C:\\Users\\ScriptKiddyMonkey\\AppData\\Local\\Deckhand",
        "--rule-edits"
      ]
    }
  }
}

    Without library access (draft only):

    {
  "mcpServers": {
    "deckhand": {
      "command": "C:\\Users\\ScriptKiddyMonkey\\AppData\\Local\\Deckhand\\Deckhand.exe",
      "args": ["--mcp"]
    }
  }
}

    The same for Codex, in config.toml:

    [mcp_servers.deckhand]
command = "C:\\Users\\ScriptKiddyMonkey\\AppData\\Local\\Deckhand\\Deckhand.exe"
args = ["--mcp", "--data", "C:\\Users\\ScriptKiddyMonkey\\AppData\\Local\\Deckhand", "--rule-edits"]

    The paths above are samples. Yours come from the setup window.

    Warning

    In JSON and in TOML double-quoted strings, every backslash in a Windows path is written twice (C:\\Users\\...). A single backslash breaks the file or silently changes the path. Copying from Deckhand gives you the correct form.

    Which program path is used

    • Standalone build: Deckhand uses its stable copy, Deckhand.exe in its own application data folder, when that file exists. Otherwise it uses the exe that is running. A portable exe that you move later breaks an entry that points at the old place, so paste a fresh entry after moving it.
    • Store build: Deckhand uses the launch alias deckhand-store.exe in %LOCALAPPDATA%\Microsoft\WindowsApps, if that alias exists. If it does not, the setup window says that local client setup is not available in this installation. Use the standalone build for MCP until it does.

    What --data is

    --data names the profile folder, the folder where Deckhand keeps its library. It must be an absolute path to a folder that already exists. It is what lets the connection queue items for the running app and read your disabled rules. --rule-edits is only accepted right after --data. Without --data the connection cannot reach the app at all.

    Claude Desktop

    Add the deckhand entry from above to the mcpServers section of Claude Desktop's MCP configuration, then quit and restart Claude Desktop. In a new chat the Deckhand tools should be listed among the available tools.

    Claude Code

    Claude Code registers a local stdio server with its own command. The program and arguments are the ones from the setup window, for example:

    claude mcp add deckhand -- "C:\Users\ScriptKiddyMonkey\AppData\Local\Deckhand\Deckhand.exe" --mcp --data "C:\Users\ScriptKiddyMonkey\AppData\Local\Deckhand" --rule-edits

    Here the paths are written as in a normal PowerShell command, with single backslashes. Check the result with claude mcp list. See Claude Code's own MCP documentation for scopes and options, which Deckhand does not control.

    Cursor, Codex and other clients

    Any client that can launch a local stdio MCP server works the same way: a command (the path to Deckhand.exe) and arguments. Use the JSON entry if the client takes mcpServers JSON, the TOML entry for Codex.

    Deckhand speaks MCP protocol versions 2025-11-25, 2025-06-18, 2025-03-26 and 2024-11-05. It answers with the version the client asks for, or 2025-11-25 if it asks for a version Deckhand does not know. Structured results (structuredContent) and tool titles and output schemas are sent for the two newest versions, and the same JSON is always sent as text too. Deckhand does not support JSON-RPC batches (removed from the protocol in 2025-06-18), and a request id must be a string or a number: send one message per line. A message longer than 1 MiB is answered with an error and skipped, and the connection stays open. Cancellation notifications are accepted and ignored (every tool answers at once), and nothing but JSON messages, one per line, is ever written to standard output; diagnostics go to standard error. The process ends when the client closes its input.

    Try it

    Restart the client and ask:

    Help me organise invoice PDFs in Downloads. Ask me what you need before drafting a rule.

    In clients that list MCP prompts you can also pick write_rule and fill in the goal. A working connection shows the assistant calling deckhand_get_authoring_catalogue first. Then see Tools reference.

    Test on fake files

    Deckhand.exe --mcp-test is a separate mode for trying an assistant without risk. It takes no other arguments, builds a fake inbox of sample files in a temporary folder for each connection, and offers four extra deckhand_test_ tools to save a simple move rule, preview it and run it on those fake files. It never touches your real folders and has no access to your library. Register it as a second server with "args": ["--mcp-test"].
