    MCP tools reference

    Every tool, resource and prompt the Deckhand MCP connection offers, with parameters, results, errors and an example prompt.

    A connection offers up to eleven tools, four resources and two prompts. Which tools you get depends on how the client starts Deckhand, see Set up an AI client.

    ToolNeedsChanges anything?
    deckhand_get_authoring_cataloguealwaysNo
    deckhand_get_authoring_guidealwaysNo
    deckhand_validate_draftalwaysNo
    deckhand_prepare_draftalwaysNo
    deckhand_submit_rule--dataQueues one new rule, switched off
    deckhand_list_editable_rules--data --rule-editsNo
    deckhand_get_editable_rule--data --rule-editsNo
    deckhand_propose_rule_edit--data --rule-editsQueues a proposal for your review
    deckhand_request_rule_preview--data --rule-editsQueues a request for your review
    deckhand_get_request_status--data --rule-editsNo
    deckhand_list_requests--data --rule-editsNo

    Annotations, results and errors

    • Annotations. Every tool carries MCP annotations. The seven read-only tools set readOnlyHint and idempotentHint true. The three that queue something (deckhand_submit_rule, deckhand_propose_rule_edit, deckhand_request_rule_preview) set readOnlyHint false, destructiveHint false and idempotentHint false, because every call queues another item. None of them reaches outside Deckhand (openWorldHint false).
    • Results. Every result is JSON, sent as text. With protocol 2025-06-18 or 2025-11-25 the same JSON is also sent as structuredContent, and tools/list adds a title and a outputSchema to each tool. Older protocol versions get the plain tool list without those two fields.
    • Cancellation and progress. Every tool answers immediately, so there is nothing to cancel or to report progress on. A notifications/cancelled message is accepted and ignored, as the protocol allows, and never gets a reply.
    • Errors the model can fix. A failed call comes back as a normal tool result with isError: true. The JSON has valid: false or an error text, and usually a hint written for that error (a field that cannot be edited lists the editable ones; a script or command says they are not available through MCP; a stale revision says to read the rule again; a full queue says 32 requests are waiting and to review them in Deckhand). A request nested deeper than 64 levels also comes back as an error result with its own request id. Wrong or extra arguments are reported this way too, so the assistant can read the message and call again.
    • Protocol errors. Only an unknown tool name, or a tool this connection does not offer (such as deckhand_submit_rule without --data), is a JSON-RPC error (-32602) with a message that says what to do.

    The connection also offers four documents as MCP resources and two prompts, for clients that support them. See Resources and prompts.

    Authoring tools (always available)

    deckhand_get_authoring_catalogue

    No parameters; extra arguments are refused. Returns guide_version, variables (every built-in variable), transforms (every {id>transform} step) and draft_schema (the JSON schema of a draft). An assistant should call it before writing a draft.

    Example prompt: "Which variables can a Deckhand rule use for the date a PDF was created?"

    deckhand_get_authoring_guide

    No parameters. Returns guide, the offline authoring guide as text. The same text is in Settings → AI integrations → View AI reference... and in the deckhand://authoring/guide resource.

    deckhand_validate_draft

    Parameter: draft (object, required), the draft envelope to check, for example {"deckhand_export":1,"rules":[...]}. Nothing is saved.

    Returns valid (true or false), errors and warnings. For drafts that do not match the schema, the result has error_details (path, code, message, allowed values) instead of plain errors, plus a hint. Validation uses the same checks as import in the app, plus limits: names up to 200 characters, text values and templates up to 4000, paths up to 1000. An absolute destination may not contain .., and every {token} in a destination or name must be a known variable (too_long, path_traversal and unknown_token in error_details). It does not look at your files.

    Example prompt: "Write a rule that moves invoices from Downloads to Documents\Invoices, and check it with Deckhand before showing it to me."

    deckhand_prepare_draft

    Parameter: draft (object, required). Validates like the tool above. If the draft is valid, the result also contains draft: the same JSON with every rule set to enabled: false. The assistant can give you that JSON to save and import under Rules → Import.

    Example prompt: "Give me a file I can import, with the rule switched off."

    Submitting a new rule (needs --data)

    deckhand_submit_rule

    Parameter: draft (object, required), a draft with exactly one rule.

    Returns {"status":"queued","id":"mcp_...","enabled":false} or an error result with valid: false, errors and a hint. The running app picks queued rules up within a few seconds and adds each one to Rules, switched off, with a notice. If the app is closed, the rule arrives the next time it opens this profile. "Queued" only means that the request was accepted.

    A submitted draft is refused when it:

    • fails validation;
    • holds more than one rule, or any preset, custom variable or script (use Rules → Import for those);
    • contains a Run command or Run script action;
    • finds the inbox full (32 drafts are waiting: review them in Deckhand under Rules, Review AI requests, or open the app so it can receive them).

    The rule is added without a group, and its enabled flag is forced off.

    Example prompt: "Add that rule to Deckhand."

    Reading and changing existing rules (needs --rule-edits)

    These tools only see rules that are switched off and have no Run command or Run script action. A rule that is on, or that runs a command or script, is invisible to them and cannot be edited this way.

    deckhand_list_editable_rules

    Optional parameters: limit (1 to 200, default 50) and offset (0 or more, default 0). Returns rules (one page of eligible rules), total, next_offset (the offset of the next page, null on the last page) and a note. Each entry has rule_id, name, group, enabled (always false here), folders (the watch folder paths) and same_name_count. same_name_count counts every rule with the same name, case ignored, enabled or not. Above 1 means the name is ambiguous.

    Example prompt: "Which of my Deckhand rules could you help me change?"

    deckhand_get_editable_rule

    Parameter: rule_id (string, required), from the list, never the name. Returns rule, the full saved definition, and revision, a fingerprint of that exact saved version. Fails, with a hint to list the rules again, if the rule no longer exists, was switched on, or has a command or script action.

    Example prompt: "Open the 'Invoices' rule and tell me what it does."

    deckhand_propose_rule_edit

    Parameters: rule_id, revision (both required) and changes (object with at least one of name, note, folders, condition, actions). Any other field is refused. Each field you send replaces the saved field as a whole. The result must still be a valid rule using built-in variables and no command or script actions, and it must differ from the saved rule.

    Returns {"id":"edit_...","status":"pending_review"}. Nothing is saved yet. The change waits under Rules → Review AI requests.... If the rule changed since the assistant read it, revision no longer matches and the proposal is refused: the assistant must read the rule again. At most 32 requests can wait at once.

    Example prompt: "Change the Invoices rule so it only matches PDFs."

    deckhand_request_rule_preview

    Parameters: rule_id and revision (both required). Asks you to open a preview of the saved rule. Returns {"id":"edit_...","status":"pending_review"}. The preview opens in Deckhand only after you click Open preview in the review window. It counts toward the same limit of 32.

    Example prompt: "Ask me to preview the Invoices rule."

    deckhand_get_request_status

    Parameter: request_id (string, required), the id returned by a propose or preview call. Returns id and status:

    StatusMeaning
    pending_reviewWaiting for you in Deckhand.
    appliedYou applied the edit. The rule stays disabled.
    preview_handed_offYou opened the preview, or chose Apply and preview.
    discardedYou discarded the request.
    unknownNo such request, or an old one that was cleaned up.

    Once desktop work has started, applied and preview_handed_off can carry a work object with a phase and totals only:

    phaseExtra fields
    previewing, preview_canceled, preview_failed, runningnone
    preview_finishedscanned, matched, would_fail, truncated
    run_finisheddone, skipped, failed, canceled
    run_stopped_before_execution, run_interruptednone
    run_recovereddone, skipped, failed

    File names, paths and messages derived from files are never included. Deckhand keeps the 64 most recent finished requests.

    Example prompt: "Did I apply that edit? What did the preview find?"

    deckhand_list_requests

    Optional parameters: limit (1 to 200, default 50), offset (0 or more) and status (queued, pending_review, applied, preview_handed_off, discarded or rejected). Lists what this connection has put in the queue, newest first, so an assistant that lost an id can find it again and can see what is still waiting. Returns requests, total and next_offset (null on the last page), paged like deckhand_list_editable_rules.

    Each entry has id, kind (new_rule, edit or preview), status, updated_at (UTC, RFC 3339) and updated_at_unix. The statuses are the ones of deckhand_get_request_status, plus queued (a new rule from deckhand_submit_rule that the app has not received yet) and rejected (a queued rule the app refused). Entries for edits and previews also carry rule_id and rule_name, but only while that saved rule is still one the connection may see (switched off, no command or script action); otherwise both are null. applied and preview_handed_off entries add the same work totals as the status tool. New-rule entries show only the id, kind, status and time. Nothing else is returned: no rule contents, no paths, no file names. A request waiting in the queue is listed even if it is old; receipts follow the same limit of 64 as the status tool.

    Example prompt: "What requests of yours are still waiting for me to review?"

    Resources and prompts

    Every connection, in every mode, offers four read-only resources (resources/list, resources/read):

    URITypeContent
    deckhand://authoring/guideMarkdownThe authoring guide
    deckhand://authoring/examplesMarkdownWorked example drafts
    deckhand://authoring/schemaJSONThe JSON schema of a draft
    deckhand://authoring/catalogueJSONBuilt-in variables and transforms

    They are bundled documentation and contain nothing from your PC. Subscriptions are not supported.

    Two prompts (prompts/list, prompts/get) give clients a ready-made starting point, for example as slash commands:

    PromptArgumentsWhat it asks the assistant to do
    write_rulegoal (required), folderRead the guide and catalogue, ask about anything ambiguous, draft with portable paths, validate, then queue the rule with deckhand_submit_rule (or return JSON with deckhand_prepare_draft when the connection cannot submit), and say plainly that the rule is switched off.
    explain_rulerule (required)Explain a rule in plain language and point out surprises such as overwrites, deletes and broad matches. With library access, rule can be a rule_id that the assistant reads with deckhand_get_editable_rule. Otherwise paste the rule JSON.

    Prompts only produce text for the assistant. They do not change anything.

    Example conversation

    1. You: "Make a rule that files invoice PDFs from Downloads into Documents\Invoices."
    2. The assistant asks which folder and what counts as an invoice, then reads the catalogue.
    3. It validates its draft, fixes a warning, then calls deckhand_submit_rule.
    4. Deckhand shows "Deckhand MCP added a disabled rule". You open the rule, check it and run a preview.
