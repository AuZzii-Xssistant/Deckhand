    MCP overview

    What MCP is, what a connected AI client can do with Deckhand, and where to start.

    MCP (Model Context Protocol) is a standard way for an AI client, such as Claude Desktop, Claude Code, Cursor or Codex, to start a small local program and use the tools it offers. Deckhand contains such a program. When your client starts it, the client gets a set of Deckhand tools it can call while you chat.

    Local MCP is a preview feature in Deckhand 0.9.50.

    Why use it

    Without MCP you can still ask any AI tool for a rule: it writes JSON, you save the file and import it (see Writing rules with an AI assistant). With MCP the same assistant can do the steps itself:

    • read Deckhand's rule guide, examples, schema and variable catalogue (as tools or as MCP resources), so it uses only fields that exist;
    • start from two built-in prompts, write_rule and explain_rule, in clients that show MCP prompts;
    • check a draft with Deckhand's own validator and fix the errors before you see it;
    • hand the finished rule to the running app, where it arrives switched off;
    • optionally read your disabled rules, suggest edits to them and ask you to open a preview.

    You stay in charge. The connection cannot switch a rule on, cannot start a scan or a run by itself and cannot move or delete a file. See Safety model.

    How it works

    1. You add a deckhand entry to your AI client's MCP configuration. Deckhand shows the entry for you under Settings → AI integrations → Connect an AI client....
    2. The client starts Deckhand.exe --mcp in the background when it needs it. The client and this process talk over standard input and output on your own PC. No port is opened and nothing is sent over the network by Deckhand.
    3. The process answers tool calls. The running Deckhand window stays the place where you review and decide.

    The AI model itself runs wherever your client runs it, usually at the provider. See What your AI provider may see.

    Two kinds of connection

    Draft onlyWith library access
    Command arguments--mcp--mcp --data "<profile folder>" --rule-edits
    Tools4: guide, catalogue, validate, prepare11: those 4, plus submit a rule and six tools for disabled rules and your requests
    Sees your rulesNoNames, ids, folders and definitions of eligible disabled rules
    Can reach the appNoYes, by queuing items you review
    Resources and prompts4 resources, 2 promptsThe same

    "Library access" is the name of the choice Use the library currently open in Deckhand, which is ticked by default in the setup window. The tools are described in Tools reference.

    The usual workflow

    1. You describe the job. The assistant asks for missing paths and criteria.
    2. It reads the catalogue and writes a draft.
    3. It validates the draft and corrects errors.
    4. With library access it submits the rule, which appears in Rules switched off. Without it, it gives you prepared JSON to import yourself.
    5. You open the rule, read it and preview it on a real folder.
    6. You switch it on yourself, or run it from the preview.
