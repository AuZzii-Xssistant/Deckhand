Privacy Policy

Deckhand: File Organiser
Publisher: AuZzii-Xssistant
Effective date: 19 November 2026

Deckhand is a desktop app that organises files on your own computer. This policy explains what the app does with your information, what the publisher does and does not receive, and what you control. In short: your files, rules and history stay on your device, and the publisher receives none of them.

1. What the publisher collects

Nothing. Deckhand has no account or sign-in, no analytics, no crash reporter and no telemetry, and it does not automatically upload your files, file contents, rules, history or logs to the publisher or to any other server. The app does not run a server and does not need an internet connection to work.

The publisher therefore holds no personal data about you from the app and cannot look up, export or delete your Deckhand data. It exists only on your device.

2. Files and local processing

Deckhand accesses the files and folders you select or configure in rules. Depending on your rules and settings it may read file names, paths, sizes and dates, embedded metadata (for example document, audio or photo details), file hashes and file contents, and it may open archives to list or extract them. Optional OCR recognises text in images and scans using the text recogniser built into Windows, on your device. Files can contain personal or sensitive information. Deckhand uses it only to evaluate rules, show previews, perform the actions you set up and record the results.

Actions you configure can move, copy, rename, compress, extract, tag or delete files, or send them to the Recycle Bin. Deckhand shows a preview before a manual run and keeps undo information where an action can be taken back. You are responsible for the rules you switch on, so try new rules on copies of your files first.

3. What is stored on your device

Deckhand stores the following in its data folder, or under the current user's account where noted:

  • Settings, rules, presets, variables, scripts, schedules, tags and file-type lists.
  • Run history, the activity log, per-rule memory of files already handled, and undo and recovery data. These can contain file names, folder paths, destinations and error messages.
  • Optional Windows integrations that you switch on: starting with Windows, the system tray icon, and Explorer right-click menu entries. These are stored under the current user's account and are removed when you switch them off.
  • Temporary files while archives are extracted or scripts run.

Access to these files is governed by the permissions of your Windows account and device. Anyone with sufficient access to the data folder can read them, and Deckhand does not encrypt the folder. Deckhand keeps history for the period you choose in Settings, and you can clear it there. Backups and exports you save yourself stay where you put them until you delete them.

4. Network use

Deckhand does not make network requests to send your information anywhere. It does not check for updates by itself. Links in the app, such as the project page or support links, open in your default web browser, and what that browser or website then does is covered by their own policies. Deckhand shows its screens using the Microsoft Edge WebView2 component that ships with Windows; Microsoft documents how that component works.

Network activity can still happen because of choices you make:

  • Cloud folders. If you enable online-only downloads, Deckhand asks your sync provider (for example OneDrive) to make a file available locally. Your provider may also synchronise changes to files in synced folders under its own privacy policy.
  • Commands and scripts. A command or script you configure can do whatever it is written to do, including reading files and sending data over the network, with the permissions it runs with. Review scripts before enabling them. Remove the script action from its rule to stop Deckhand running it.
  • Network and removable drives. Files on shared or removable drives are handled like any other files; the owner of that storage may keep logs.

5. Optional AI clients

Deckhand can describe how to write rules for an AI assistant and can run a local connection that lets an AI client you choose work with Deckhand. This is off unless you set it up. A client connected for authoring and validation only sees the rule format and the drafts you give it. If you also give it library access, it can read eligible disabled rule definitions, which may contain folder paths, and it can check aggregate preview and run totals. Your AI client may send whatever it reads to its model provider under that provider's privacy policy, so connect only clients and providers you trust, and review a draft before you import it.

6. How you get Deckhand

If you install Deckhand from the Microsoft Store, Microsoft collects download, update and usage information about the Store listing under Microsoft's privacy statement. If you download the portable program from the GitHub releases page, GitHub handles the download under GitHub's privacy statement. The publisher does not receive information about who installs or runs the app, other than what those services show to publishers, such as download counts, ratings and reviews.

7. Your choices and control

  • Choose which folders Deckhand watches, and switch rules off or delete them at any time.
  • Switch online-only downloads, automatic start, the tray icon and Explorer integration on or off in Settings, and turn OCR on or off per File contents condition.
  • Review your activity in History and the Log, set how long history is kept, and clear it.
  • Remove all local data by closing Deckhand and deleting its data folder, and uninstall it like any other app.

8. Sharing, security and children

The publisher does not sell or share your personal information because it does not receive any from the app. Deckhand processes data locally and relies on Windows for account separation and disk protection; use Windows features such as BitLocker and a locked account if your files are sensitive. Deckhand is a general-purpose utility, is not directed at children, and does not knowingly collect information from anyone.

9. Support requests and public issues

If you contact the publisher through the project's GitHub issues, anything you post, including logs, screenshots and file names, is public and handled by GitHub. Remove personal file names, folder paths and other sensitive information before posting. Do not post passwords, keys or private documents.

10. Changes to this policy

If the way Deckhand handles information changes, for example if a feature ever needs a network service, this policy will be updated before that release and the effective date above will change. Earlier versions remain available in the project's public history.

11. Contact

For privacy questions, use the Deckhand support page. GitHub issues are public, so do not include personal information.
